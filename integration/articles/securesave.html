OSL Secure Save

Server-authoritative save system for Unity using Unity Gaming Services (UGS).
All write operations are validated by a Cloud Code script before being committed to Cloud Save.
Reads are performed directly via the Cloud Save SDK on the client.

Clarification: OSL Secure Save is not a local encrypted save-file package. It is designed for server-validated Cloud Save writes through Unity Cloud Code.

Overview

OSL Secure Save prevents client-side cheating by routing all save operations through a Cloud Code endpoint (osl_master_save). The endpoint enforces:

  • Type validation — value must match the declared type for that key
  • Range validation — value must fall within MinValue/MaxValue
  • Delta validation — for AddOnly keys, the increment cannot exceed MaxDelta
  • Operation validation — each key is locked to AddOnly, Replace, or Both

Who Should Use This

Use OSL Secure Save when your project needs:

  • Server-side validation before committing player save changes
  • Guardrails against simple client-side currency, level, or inventory tampering
  • Unity Gaming Services based Cloud Code and Cloud Save integration
  • Rule-driven validation that can be updated without rebuilding the client

When Not to Use This

Do not use this package when you need purely offline local saves with no network dependency. Reads can be client-side through Cloud Save, but writes depend on Unity Cloud Code.

This package also does not replace a full custom authoritative backend for complex economies, trading, multiplayer inventories, fraud review, or cross-platform account systems.

Architecture

Client (Unity)
  │
  ├─ Write
  │     └─► OSLSaveManager.AddInt / SetInt / SetString / SetBool
  │               └─► CloudCodeService.CallEndpointAsync("osl_master_save")
  │                         └─► [Server] Load rules → Validate → CloudSave.setItem()
  │
  └─ Read
        └─► OSLSaveManager.GetAsync<T> / LoadAllAsync
                  └─► CloudSaveService.Instance.Data.Player.LoadAllAsync()

UGS Project Setup

  1. Open Unity Dashboard.
  2. Create or select a project.
  3. Enable Cloud Code, Cloud Save, Authentication, and optionally Remote Config.
  4. In the Unity Editor, link your project via Edit → Project Settings → Services.

Unity Package Setup

  1. Search for OSL Secure Save in the Unity Asset Store, or open it directly at Unity Asset Store (OSL Secure Save).
  2. Click Add to My Assets.
  3. Open Unity and navigate to Window > Package Manager.
  4. Select Packages: My Assets from the dropdown.
  5. Locate OSL Secure Save, download it, and click Import.

Next, install the required UGS SDKs via Window → Package Manager → Unity Registry:

  • Authentication (com.unity.services.authentication)
  • Cloud Code (com.unity.services.cloudcode)
  • Cloud Save (com.unity.services.cloudsave)
  • Remote Config (com.unity.services.remoteconfig) — optional

Cloud Code Endpoint Deployment

  1. Go to Dashboard → Cloud Code → Scripts and click Create Script, name it osl_master_save.
  2. Add parameters key (String, required) and operation (String, required). Do not add value as a typed parameter.
  3. Paste the contents of Assets/OSL/SecureSave/CloudCode/osl_master_save.js into the script editor.
  4. Click Save & Deploy.

Remote Config Setup (Optional)

Add a key osl_secure_save_rules of type JSON to Remote Config with your rule set:

{
  "Rules": [
    { "Key": "gold",       "Type": 0, "MinValue": 0, "MaxValue": 9999999, "MaxDelta": 10000, "AllowedOp": 0 },
    { "Key": "level",      "Type": 0, "MinValue": 1, "MaxValue": 999,     "MaxDelta": 1,     "AllowedOp": 1 },
    { "Key": "playerName", "Type": 2, "MinValue": 0, "MaxValue": 0,       "MaxDelta": 0,     "AllowedOp": 1 }
  ]
}

Type: 0 = Int, 1 = Float, 2 = String, 3 = Bool
AllowedOp: 0 = AddOnly, 1 = Replace, 2 = Both

Rule design tips:

  • Use AddOnly for soft currency increments that should be bounded.
  • Use Replace for state values such as level, display name, or flags.
  • Keep MaxDelta small enough to catch obvious tampering but large enough for legitimate rewards.
  • Treat Remote Config rules as operational policy, not as a substitute for business logic review.

Using OSLSaveManager

Initialization

await UnityServices.InitializeAsync();
await AuthenticationService.Instance.SignInAnonymouslyAsync();

Write operations

OSLSaveResult result = await OSLSaveManager.Instance.AddInt("gold", 50);
await OSLSaveManager.Instance.SetInt("level", 5);
await OSLSaveManager.Instance.SetString("playerName", "Hero");
await OSLSaveManager.Instance.SetBool("tutorialDone", true);

Read operations

int gold   = await OSLSaveManager.Instance.GetAsync<int>("gold", 0);
string name = await OSLSaveManager.Instance.GetAsync<string>("playerName", "Unknown");
Dictionary<string, object> all = await OSLSaveManager.Instance.LoadAllAsync();

Demo Scene

Assets/OSL/SecureSave/Demo/OSLBasicUsageSample.cs provides an interactive OnGUI demo.

  1. Create an empty scene and attach OSLBasicUsageSample to a GameObject.
  2. Enter Play mode and use the on-screen buttons to test Sign In, Add Gold, and Level Up operations.

Troubleshooting

Symptom Likely cause Action
Write operation fails immediately Unity Services or Authentication was not initialized Call UnityServices.InitializeAsync() and sign in before using OSLSaveManager.
Cloud Code endpoint not found osl_master_save was not deployed or name does not match Confirm the Cloud Code script name and deployment status.
Value is rejected by the server Remote Config rule blocks type, range, delta, or operation Review osl_secure_save_rules and the operation being sent.
Reads work but writes fail Client can read Cloud Save, but Cloud Code write path is misconfigured Check Cloud Code parameters, service permissions, and deployment logs.
Works in Editor but fails in build UGS project/environment mismatch Confirm the Unity project is linked to the correct UGS project and environment.
Players can still modify local display state UI state is not the authoritative save state Reload from Cloud Save after accepted writes and treat Cloud Code results as the source of truth.

Project Overview

Project Description

OSL Integration is a collection of Unity Asset Store packages aimed at providing robust, production-ready modules for networking, security, and social login.

Goals

To provide developers with lightweight, server-authoritative, and modular solutions without relying on bloated third-party SDKs where possible.

Direction (Architecture)

The project follows a Hierarchical Core Architecture to prevent bloatware in the customer's project. Upper modules can only reference lower modules (uni-directional dependency).

  • Layer 0: OSL.Core (Shared Utility): An ultra-lightweight common module used by all assets (e.g., OSLCrypto, OSLLogger).
  • Layer 1: OSL.Auth.Base (Domain Core): The authentication base that ties the social login modules together (ISignin, token verification).
  • Layer 2: OSL.Product (End Product): Single-purpose deployment units (e.g., OSL.EasyPatcher, OSL.SecureSave). Selectively references Layer 0 or Layer 1.

Progress

Currently migrating all legacy packages to the new OSL standard and generating store-ready documentation.

Future Implementations

  • Automated .unitypackage export process via Editor scripts.

Package Details (Individual Modules)

Below are the detailed descriptions and specific directions for each package within the OSL Integration suite:

1. Deterministic

  • Description: A zero-dependency, zero-allocation deterministic RNG (Random Number Generator) suite.
  • Direction: Provides a reliable and mathematically consistent foundation for lockstep multiplayer, save-state rollback, and procedural generation without floating-point drift across devices.

2. EasyPatcher

  • Description: A lightweight, streaming patch distribution system for Unity.
  • Direction: Aims to replace heavy systems like Addressables for simple patch downloads. It allows developers to push updates via native REST APIs (AWS, GCP, Azure, Unity CCD) and securely download only changed files at runtime using AES/HMAC.

3. IapClient

  • Description: A server-authoritative In-App Purchase verification wrapper.
  • Direction: Prevents client-side receipt forgery by intercepting Unity IAP callbacks and forcing a secure validation step through the developer's backend server before granting in-game rewards.

4. SecureSave

  • Description: A no-code, server-authoritative save system backed by Unity Gaming Services (UGS).
  • Direction: Eradicates client-side save manipulation. It routes all saves through UGS Cloud Code to validate data types, max deltas, and value clamps securely on the server.

5. SocialLogin

  • Description: A unified Multi-Platform Social Login solution.
  • Direction: Abstracts Apple, Facebook, Google, Steam, and Discord (Zero-SDK) behind a single ISignin interface. Employs soft dependencies (asmdef constraints) to ensure unused SDKs never bloat the project compilation.

6. SocialLoginPro

  • Description: An end-to-end secure sign-in bundle.
  • Direction: Combines SocialLogin with the TokenVerification backend. It aims to provide a complete turnkey pipeline—from client-side OAuth popups to backend cryptographic JWT/ticket verification.

7. TokenVerification

  • Description: A standalone .NET 8 Web API server boilerplate and Unity client.
  • Direction: Provides developers with a ready-to-deploy backend server (ASP.NET Minimal API) to cryptographically verify OAuth identity tokens, defeating client-side spoofing attacks.

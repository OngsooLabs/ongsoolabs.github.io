프로젝트 규칙

개발 규칙

1. 네임스페이스(Namespace) 표준화

모듈 간 충돌을 방지하고 코드 자동 완성을 쾌적하게 만들기 위해, 모든 프로젝트의 루트 네임스페이스는 OSL로 시작합니다.

  • 패턴: OSL.[ProjectName].[Module] (예: OSL.EasyPatcher.Runtime)

2. 폴더 구조(Folder Structure) 표준화

에셋 스토어 검수를 통과하고 유저 환경에서의 가시성을 확보하기 위해 아래의 디렉토리 구조를 강제합니다:

Assets/OSL/
  ├── Core/                       # 공통 유틸리티 (로깅, 암호화 등)
  ├── Editor/                     # 글로벌 에디터 유틸리티 (규칙 예외)
  └── [ProjectName]/              # 개별 에셋 패키지
       ├── package.json           # UPM 호환
       ├── Runtime/               # 메인 로직 (.asmdef)
       ├── Editor/                # 에디터 로직 (.Editor.asmdef)
       ├── Plugins/               # 외부 SDK AAR, DLL 등 격리
       ├── Samples/               # Asset Store export용 데모 씬
       ├── Samples~/              # UPM-style 샘플이 필요한 경우에만 사용
       ├── Server~/               # 백엔드 서버 소스 (유니티 임포트 제외)
       └── Documentation/         # 문서 공간
  • 표준 Unity Asset Store .unitypackage export에는 Samples/를 사용합니다.
  • Unity Package Manager 방식의 샘플 import 동작이 필요한 경우에만 Samples~/를 사용합니다.
  • 백엔드 서버 프로젝트나 백엔드 소스 zip은 패키지별 별도 사유가 없는 한 Server~/ 아래에 둡니다.

3. Assembly Definition (ASMDEF) 관리 원칙

  • 네이밍 규칙: OSL.[ProjectName].asmdef 및 OSL.[ProjectName].Editor.asmdef
  • 성능 최적화 스펙:
    • Auto Referenced: False 강제 (명시적 참조 필수).
    • Use GUIDs: True.
  • 외부 라이브러리 (Soft Dependency):
    • 외부 SDK가 없는 상태에서 임포트해도 컴파일 에러가 나지 않아야 합니다.
    • Version Defines (Define Constraints) 활용 (예: Steamworks 감지 시 OSL_HAS_STEAM 활성화). 코드 내부에서 #if 문으로 분기 처리.

4. 언어 및 주석 규칙 (Language & Commenting Rules)

  • 프로젝트 내의 모든 문서(마크다운, PDF 등)와 소스 코드의 주석(Comments)은 유니티 에셋 스토어 글로벌 배포를 위해 반드시 영어로 작성해야 합니다. (단, 개발자 참고용 내부 _KO.md 문서는 예외)

5. 호환성 및 주장 표현 규칙

  • 가능하면 호환성은 Minimum Unity Version과 Tested Unity Versions로 나누어 표기합니다.
  • 자동 테스트와 문서화된 근거가 없는 경우 every platform, every Unity version, perfect security, guaranteed zero loss 같은 절대 표현은 피합니다.
  • 대신 supported and tested platforms, reduces risk, detects tampering, server-authoritative validation path처럼 검증 범위가 명확한 표현을 사용합니다.
  • 백엔드 패키지는 지원 중인 .NET LTS 버전을 대상으로 합니다. 현재 .NET 8을 대상으로 한다면 지원 종료 전에 다음 LTS 버전으로의 호환 경로를 추적해야 합니다.

배포 및 협업 규칙

1. 버전 관리 (package.json)

모든 에셋 폴더에는 유니티 패키지 매니저(UPM)와 호환되는 package.json을 작성해야 합니다.

2. Changelog 포맷

패키지 릴리즈 노트는 아래 형식으로 통일합니다:

  • 새 버전 배포 전에는 반드시 ## [x.x.x] - Unreleased 항목을 만들어 작업 중인 변경 사항을 미리 기록해 둡니다.
  • 실제 배포 시점에 해당 항목의 날짜를 확정하여 릴리즈를 완료합니다.
## [1.1.0] - Unreleased
### Added
- Feature drafts or bug fixes currently in progress.

## [1.0.0] - 2026-07-09
### Added
- Initial release details.

3. 스토어 배포용 추출(Export) 체크리스트

  1. 의존성 자동 포함 검증: 상위 패키지 추출 시 OSL.Core 등의 필수 폴더가 포함되었는지 확인.
  2. Samples 격리 확인: Samples/ 또는 Samples~/의 테스트 코드가 Runtime 폴더를 오염시키지 않았는지 검증.
  3. Third-Party SDK 배제: 에셋 스토어 규정상 타사의 SDK는 재배포가 불가하므로, Export 시 반드시 체크 해제합니다.
  4. 민감 데이터 검열: API Key나 크레덴셜이 남아있는지 검사.
  5. 문서(Docs) 검수: 디렉토리 내 Documentation/README.pdf 유무 및 영문 작성 여부 확인.

Project Rules

Development Rules

1. Namespace Standardization

To prevent module conflicts and improve code completion, all root namespaces must start with OSL. Keep the namespace depth concise.

  • Pattern: OSL.[ProjectName].[Module] (e.g., OSL.EasyPatcher.Runtime)

2. Folder Structure Standardization

To ensure visibility in the user's environment and pass Asset Store reviews, enforce the following directory structure:

Assets/OSL/
  ├── Core/                       # Shared Utilities
  ├── Editor/                     # Global editor utilities (Exception)
  └── [ProjectName]/              # Individual Asset Package
       ├── package.json           # UPM compatibility
       ├── Runtime/               # Main game logic (.asmdef)
       ├── Editor/                # Editor logic (.Editor.asmdef)
       ├── Plugins/               # External SDKs (AAR, DLL)
       ├── Samples/               # Demo scenes
       ├── Server~/               # Backend server source (ignored by Unity import)
       └── Documentation/         # README, PDFs

3. Assembly Definition (ASMDEF) Rules

  • Naming: OSL.[ProjectName].asmdef and OSL.[ProjectName].Editor.asmdef.
  • Performance Constraints:
    • Auto Referenced: False (Explicit reference required).
    • Use GUIDs: True.
  • External Library Handling (Soft Dependencies):
    • Importing OSL files without external SDKs (e.g., Steamworks) must not cause compilation errors.
    • Use Version Defines (Define Constraints) (e.g., activate OSL_HAS_STEAM only when Steamworks is detected). Use #if OSL_HAS_STEAM in code.

4. Language & Commenting Rules

  • All documents (Markdown, PDF, etc.) within the project and source code comments must be written in English to comply with Unity Asset Store global distribution guidelines. (Internal _KO.md developer notes are the only exception).

Collaboration & Deployment Rules

1. Version Management (package.json)

All asset folders must contain a UPM-compatible package.json declaring the package name, version, and internal dependencies.

2. Export Checklist for Asset Store

  1. Dependency Inclusion: Ensure dependent folders (like OSL.Core) are checked when exporting a package.
  2. Sample Isolation: Ensure temp textures or test code in Samples/ do not pollute the Runtime/ folder.
  3. Exclude Third-Party SDKs: Third-party plugins (e.g., Facebook SDK) MUST be unchecked during export due to Asset Store redistribution rules.
  4. Censor Sensitive Data: Ensure no aws_credentials or API keys are left behind.
  5. Docs Verification: Ensure Documentation/README.pdf exists and supports English.

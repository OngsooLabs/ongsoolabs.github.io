Reader Lock Dataset Plan

This plan defines how the seed benchmark grows from 30 URLs to a 100 URL lock dataset.

Goal

The lock dataset is the release gate for reader quality drift. It should remain stable enough to run before Phase 2 work that changes extraction, quality scoring, site rules, dynamic rendering, or output formatting.

Candidate Rules

The initial lock dataset is complete. Add or replace a URL only when it meets all rules:

  • It is public HTTPS content.
  • It does not require authentication, cookies, custom headers, or proxy settings.
  • It has stable page semantics and a stable title or heading.
  • It is appropriate to store as a benchmark target.
  • It can pass with mustContain, mustNotContain, and minCharacters checks.
  • It does not require logging response body, raw HTML, or extracted content for diagnosis.

Prefer official documentation, standards bodies, public encyclopedias, and government or institutional articles. Avoid pages that routinely block automation, personalize content, rotate major text, or intentionally serve anti-bot challenges.

Promotion Workflow

  1. Add candidate URLs in batches of 10 to 20.
  2. Run the candidate batch with the local runner.
  3. Replace blocked or unstable pages rather than weakening expectations.
  4. Keep mustContain values broad but meaningful, usually the product, standard, article, or concept name.
  5. Use mustNotContain for retrieval failure markers such as Access Denied and Too Many Requests.
  6. Promote candidates to the lock dataset only after a clean local pass.

Runner Commands

Run a dry run first:

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-reader-benchmark.ps1 -DatasetPath .\artifacts\benchmarks\reader-seed-dataset.json -DryRun

Run a real benchmark after Scraper and TextProcessor are running:

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-reader-benchmark.ps1 -BaseUrl http://localhost:5243 -DatasetPath .\artifacts\benchmarks\reader-seed-dataset.json

Lock Dataset Exit Criteria

The 100 URL lock dataset is complete when:

  • reader-lock-dataset.json contains exactly 100 URLs. Completed.
  • All items pass dataset shape tests. Completed.
  • A local full run passes 100/100. Completed.
  • Known flaky pages are replaced or marked for exclusion before lock. Completed.
  • The README records the lock baseline date and result. Completed.
  • The Phase 2 entry gate marks Benchmark URL 100+ secured as completed. Completed.

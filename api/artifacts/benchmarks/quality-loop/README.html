Reader Quality Improvement Loop

This directory keeps the reviewable inputs and templates for the Reader quality loop.

Corpus roles

  • live-core.json selects 12 representative cases from the existing 100 URL lock dataset. It is a daily observation sample; it does not change the release gate.
  • discovery-candidates.json is a human-reviewed exploration queue. Add up to three public candidates for each of news, technical-documentation, and product-page; do not add them to the lock dataset automatically.
  • snapshot-manifest.json records the existing deterministic Reader test fixtures. No raw external HTML is captured yet. Add an external snapshot only after its storage and reuse are approved.

Safety and promotion rules

  • The runner stores case IDs and SHA-256 URL fingerprints, not raw URLs, response bodies, request bodies, cookies, headers, or extracted content.
  • A Live failure is an observation, not a product regression by itself. BLOCKED_BY_SITE, UPSTREAM_NOT_FOUND, and UPSTREAM_ERROR_PAGE are external failures; timeouts and fetch failures are infrastructure candidates.
  • Only deterministic snapshot failures become REGRESSION automatically.
  • The runner proposes an improvement candidate only after the same case has a product-quality candidate classification in at least two retained runs. It never edits issues, corpus files, source code, Git state, or deployment configuration.
  • Promote or replace a Lock URL only through human review after repeated stable runs. Replace blocked or unstable pages rather than weakening an expectation.

Daily execution

Run the script from the repository root:

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-reader-quality-loop.ps1

It runs the solution tests, ensures the local Reader health endpoint is available, executes the daily Live core and any approved discovery candidates, writes a structured run record, and writes a Markdown report under runs/<run-id>/.

Each run.json and report.md includes a work assessment. Work is required only for a deterministic regression, an environment failure that prevented completion, or a repeated product-quality candidate. The assessment includes its reason and the related run/report paths; issue and improvement-plan templates are listed only when human review should create follow-up work.

The runs/ directory is intentionally reviewable and is not committed automatically. A scheduled run leaves its results for a human to inspect and commit deliberately if they should become durable project history.

Weekly expansion

Use the existing full lock command for the weekly Live gate:

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-reader-benchmark.ps1 -BaseUrl http://localhost:5243 -DatasetPath .\artifacts\benchmarks\reader-lock-dataset.json

After the weekly run, summarize the retained daily run.json files by category, status, and duration. This initial change intentionally does not register a weekly automation.

AI Reader API (v1.0)

URL → clean, LLM-ready Markdown + structured JSON.

AI Reader API removes common webpage clutter and extracts readable main content from public webpages for AI agents, RAG pipelines, and content-processing workflows. It returns Markdown, plain text, or structured JSON together with optional source metadata.

AI Reader API is built and operated by OngsooLabs. Official resources include the Reader sample, API guide, and support.

RapidAPI manages its own subscriptions, credentials, request quotas, and billing. OngsooLabs Direct uses separate accounts, API keys, credits, and billing. Credentials and entitlements do not transfer between the two channels. The Quick Start in this listing continues to use RapidAPI credentials.

What It Solves

Modern AI systems need clean source content, not full webpages packed with navigation, ads, scripts, footers, sidebars, and duplicate layout text. AI Reader API helps convert public web pages into a format that is easier to embed, summarize, index, search, and pass into LLM prompts.

Use it when you need to:

  • Let an AI agent read and process the content behind a URL.
  • Clean webpage bodies before indexing them in a RAG ingestion pipeline.
  • Convert article and documentation pages into Markdown or structured JSON.
  • Prepare web content for vector databases such as Pinecone, Qdrant, Milvus, Weaviate, or pgvector.
  • Split long pages into overlapping chunks for embedding ingestion.

What You Get

  • Clean Markdown, Text, or JSON: Choose the output format that fits your workflow.
  • Boilerplate Removal: Filters common page noise such as navigation, scripts, ads, footers, and repeated layout text.
  • Simple Core Response: Read the extracted content first, then use optional usage, quality, and execution metadata when you need cost visibility, debugging, or RAG pipeline tuning.
  • Optional Chunking: Create overlapping chunks directly from extracted page content or from raw text.
  • Site-Aware Extraction Modes: Tune extraction for article, documentation, product, forum, or generic content.
  • Hybrid Retrieval: Uses static HTTP retrieval first and dynamic browser rendering when needed.
  • Output Controls: Toggle tables, code blocks, images, links, content, and metadata.

Token counts and embedding costs are estimates intended for planning LLM and embedding workloads. OpenAI uses the closest native encoding; Claude, Gemini, and Llama counts are approximations.

Public Endpoints

This RapidAPI listing exposes four REST endpoints:

  • GET /v1/reader - Convert a webpage using URL query parameters.
  • POST /v1/reader - Convert a webpage using JSON options.
  • POST /v1/reader/document - Public Beta: convert a public text-layer PDF URL to Markdown.
  • POST /v1/reader/chunk - Split raw text into overlapping chunks.

The public API is designed for safe processing of public webpages and focuses on URL-based extraction, output formatting, token estimation, and chunking controls.

Read a Public PDF Document (Public Beta)

POST /v1/reader/document reads public HTTPS text-layer PDF URLs only. It always returns Markdown and supports the existing tokenizer and optional chunking controls. File uploads, DOCX, OCR, encrypted PDFs, document generation, browser rendering, and custom headers are not supported.

The Public Beta revalidates redirect targets against the URL safety policy, limits downloads to 10 MiB and parsing to 100 pages, and charges one response credit only on success. execution.profile is document; execution.usedBrowser is always false. If the upstream PDF URL returns 404 or 410, the API returns HTTP 404 with status: "failed", error.code: "UPSTREAM_NOT_FOUND", error.retryable: false, and usage.credits: 0. This means the target PDF is unavailable; it is not a Reader service outage. A document with no extractable text fails with DOCUMENT_NO_TEXT_LAYER; mixed text/image PDFs return extractable text and a PARTIAL_DOCUMENT_TEXT warning.

Quick Start

Convert a Webpage

Input boundary: Submit a publicly accessible URL in one synchronous request. Pages that require sign-in, payment, authentication, custom headers, cookies, or bypassing bot/security controls are not supported. Batch, crawl, and asynchronous-job endpoints are not available.

  1. Create or sign in to your RapidAPI account and subscribe to an available AI Reader API plan.
  2. Copy your X-RapidAPI-Key from the RapidAPI dashboard.
  3. Run this request. It uses https://example.com/, a public page intended for integration examples.

macOS or Linux

curl --request POST \
  --url https://ai-reader-api.p.rapidapi.com/v1/reader \
  --header 'Content-Type: application/json' \
  --header 'X-RapidAPI-Host: ai-reader-api.p.rapidapi.com' \
  --header 'X-RapidAPI-Key: <your-rapidapi-key>' \
  --data '{
    "url": "https://example.com/",
    "output_format": "markdown",
    "mode": "generic",
    "enable_chunking": false
  }'

Windows PowerShell

$headers = @{
  "X-RapidAPI-Key" = "<your-rapidapi-key>"
  "X-RapidAPI-Host" = "ai-reader-api.p.rapidapi.com"
}

$body = @{
  url = "https://example.com/"
  output_format = "markdown"
  mode = "generic"
  enable_chunking = $false

$response = Invoke-RestMethod -Method Post `
  -Uri "https://ai-reader-api.p.rapidapi.com/v1/reader" `
  -Headers $headers `

$response.status
$response.content.value
$response.usage.credits

How to Read the Response

Most users only need these fields:

  • content.value: The extracted Markdown or plain text when output_format is markdown or text.
  • content.article: The structured article object when output_format is json.
  • url and finalUrl: The submitted URL and the resolved URL after any upstream redirects. Cached responses preserve the resolved finalUrl.
  • usage.credits: OngsooLabs reader response credit metadata.
  • status: success, partial, or failed.

Execution Profile and Render Retry

execution.profile is internal execution metadata, not a request selector. fast means the read completed through a static path. standard means the read used a browser-oriented path: a dynamic site rule, force_dynamic=true, or a static-to-browser fallback.

When a static extraction does not meet the main-body quality gate, the reader automatically attempts browser rendering once before returning partial. If a retryable RENDER_REQUIRED error or partial response still includes recommendedProfile: "standard", retry the same request with force_dynamic: true. Do not add a profile field; clients cannot choose fast or standard. Static, browser, and cache-backed successful reads all return usage.credits = 1.

Static verification pages, including Cloudflare challenges, are treated as browser-fallback candidates. Cloudflare runtime scripts alone do not invalidate an otherwise usable extracted body; a remaining verification page without usable content is returned as BLOCKED_BY_SITE. Confirmed upstream 404/410 responses and RapidAPI soft 404 pages are returned as errors without browser fallback.

Use these fields when you need more control:

  • metadata: Available source metadata plus word count and reading time. The page title is the top-level title field; it is not metadata.title. Word count includes a CJK and Hangul estimate for languages that do not rely on whitespace between words.
  • usage: Character count, token estimate, chunk count, and response credit metadata.
  • quality: v0 extraction signals for debugging and pipeline tuning. linkDensity is based on visible Markdown link text, excluding image Markdown. score and grade are intentionally null in v0.
  • execution: Runtime details such as cache status, browser usage, retry count, and duration.
  • chunks: Optional overlapping chunks when enable_chunking is true.

Credits and RapidAPI Quota

The v1 launch credit model is intentionally simple:

  • Successful GET /v1/reader and POST /v1/reader calls return usage.credits = 1.
  • A partial response preserves the extracted content but returns usage.credits = 0 and error.code = "PARTIAL_CONTENT" when the main body does not meet the quality gate.
  • Failed reader calls return usage.credits = 0.
  • Output format, reader mode, optional metadata, optional chunking, browser fallback, and cache validation do not change the launch credit value. usage.credits is a reader-processing value returned by the API. It is separate from your RapidAPI plan's request quota; a request may still count toward that quota even when usage.credits is 0.

Your active RapidAPI plan controls the applicable request quota, limits, and commercial terms. Check the active RapidAPI listing for plan-specific details.

1. GET /v1/reader

Convert and analyze a target webpage using query parameters. This is convenient for simple integrations, browser testing, and quick API calls.

Query Example

GET /v1/reader?url=https%3A%2F%2Fexample.com%2Farticle-url&output_format=markdown&mode=article

Query Parameters

  • url (string, required): Target public webpage URL.
  • output_format (string): markdown, text, or json. Default: markdown.
  • tokenizer (string): openai, claude, gemini, or llama. Default: openai.
  • mode (string): article, documentation, product, forum, or generic. Default: generic.
  • force_dynamic (boolean): Force browser rendering instead of static retrieval. Default: false.
  • disable_css (boolean, nullable): Override site-rule CSS loading during dynamic rendering.
  • enable_chunking (boolean): Include overlapping chunks in the response. Default: false.
  • chunk_size_tokens (integer): Target chunk size in tokens, from 16 through 8192. Default: 500.
  • overlap_size_tokens (integer): Token overlap between chunks. Must be non-negative and smaller than chunk_size_tokens. Default: 100.
  • output_content (boolean): Include cleaned content or article body. Default: true.
  • output_metadata (boolean): Include extracted page metadata, word_count, and reading_time_minutes. It does not control usage, quality, or execution. Default: true.
  • output_tables (boolean): Include markdown tables. Default: true.
  • output_code_blocks (boolean): Include code blocks. Default: true.
  • output_images (boolean): Include image markdown. Default: false.
  • output_links (boolean): Include hyperlinks. Default: false.

3. POST /v1/reader/chunk

Split raw input text into overlapping token or character segments without fetching a webpage. Use this endpoint when you already have text and only need chunk preparation for embeddings or retrieval.

This endpoint keeps its original successful array response. Failure responses use the standardized error envelope. Full success-envelope alignment for chunking is outside the v1 launch baseline.

Request Example

{
  "text": "The long raw text content you want to split into overlapping chunks for embedding ingestion...",
  "tokenizer": "openai",
  "use_tokens": true,
  "chunk_size_tokens": 500,
  "overlap_size_tokens": 100
}

Request Body Parameters

  • text (string, required): Raw text to split. Maximum: 1,000,000 characters.
  • tokenizer (string): openai, claude, gemini, or llama. Default: openai.
  • use_tokens (boolean): Use token-based chunking when true; use character-based chunking when false. Default: true.
  • chunk_size_tokens (integer): Target chunk size in tokens, from 16 through 8192. Default: 500.
  • overlap_size_tokens (integer): Token overlap between chunks. Must be non-negative and smaller than chunk_size_tokens. Default: 100.
  • chunk_size (integer): Target chunk size in characters when use_tokens is false, from 64 through 65536. Default: 1000.
  • overlap_size (integer): Character overlap when use_tokens is false. Must be non-negative and smaller than chunk_size. Default: 200.

Requests that would produce more than 2,048 chunks fail with HTTP 400 and error.code = "INVALID_REQUEST" before a chunk array is created. Text or parameter limits use the same non-retryable error contract and return usage.credits = 0.

Error Responses

Capacity Rejection

If the shared Reader execution limit is full, the Reader, document, and chunk endpoints return HTTP 429 immediately instead of queuing the request. The standard failure envelope sets error.code to RATE_LIMIT_EXCEEDED and error.retryable to true; the response includes a positive Retry-After header in seconds. Wait for that duration before retrying. This is capacity protection, not a per-customer quota response.

Partial Content

The endpoint returns HTTP 200 with status: "partial" when it can return some extracted content but the main body is too short or only a metadata description was available. The reader automatically attempts browser rendering once after a partial static extraction; treat a remaining partial response as non-success for ingestion and billing purposes. If error.retryable is true, retry once with force_dynamic: true.

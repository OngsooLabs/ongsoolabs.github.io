AI Reader API (v1.0)

Turn messy webpages into clean, LLM-ready content.

AI Reader API extracts the meaningful body from public webpages and returns clean Markdown, plain text, or structured JSON for RAG pipelines, AI agents, knowledge bases, and automated web ingestion workflows.

Instead of sending noisy HTML to your LLM stack, use AI Reader API to remove common layout clutter, estimate token usage, and optionally split content into embedding-ready chunks in one request.

Why Use AI Reader API?

Modern AI systems need clean source content, not full webpages packed with navigation, ads, scripts, footers, sidebars, and duplicate layout text. AI Reader API helps convert public web pages into a format that is easier to embed, summarize, index, search, and pass into LLM prompts.

Use it when you need to:

  • Build RAG pipelines from public articles, docs, forums, and product pages.
  • Give AI agents a reliable way to read webpages before reasoning over them.
  • Convert HTML pages into clean Markdown for LLM prompts and summaries.
  • Prepare web content for vector databases such as Pinecone, Qdrant, Milvus, Weaviate, or pgvector.
  • Split long pages into overlapping chunks for embedding ingestion.

What You Get

  • Clean Markdown, Text, or JSON: Choose the output format that fits your workflow.
  • Boilerplate Removal: Filters common page noise such as navigation, scripts, ads, footers, and repeated layout text.
  • Metadata & Usage: Returns available title, author, published date, language, excerpt, lead image, reading metrics, token usage, chunk count, credits, execution metadata, and quality signals.
  • Optional Chunking: Create overlapping chunks directly from extracted page content or from raw text.
  • Site-Aware Extraction Modes: Tune extraction for article, documentation, product, forum, or generic content.
  • Hybrid Retrieval: Uses static HTTP retrieval first and dynamic browser rendering when needed.
  • Output Controls: Toggle tables, code blocks, images, links, content, and metadata.

Token counts and embedding costs are estimates intended for planning LLM and embedding workloads. OpenAI uses the closest native encoding; Claude, Gemini, and Llama counts are approximations.

Public Endpoints

This RapidAPI listing exposes three public endpoints:

  • GET /v1/reader - Convert a webpage using URL query parameters.
  • POST /v1/reader - Convert a webpage using JSON options.
  • POST /v1/reader/chunk - Split raw text into overlapping chunks.

The public API is designed for safe processing of public webpages and focuses on URL-based extraction, output formatting, token estimation, and chunking controls.

1. GET /v1/reader

Convert and analyze a target webpage using query parameters. This is convenient for simple integrations, browser testing, and quick API calls.

Query Example

GET /v1/reader?url=https%3A%2F%2Fexample.com%2Farticle-url&output_format=markdown&mode=article

Query Parameters

  • url (string, required): Target public webpage URL.
  • output_format (string): markdown, text, or json. Default: markdown.
  • tokenizer (string): openai, claude, gemini, or llama. Default: openai.
  • mode (string): article, documentation, product, forum, or generic. Default: generic.
  • force_dynamic (boolean): Force browser rendering instead of static retrieval. Default: false.
  • disable_css (boolean, nullable): Override site-rule CSS loading during dynamic rendering.
  • enable_chunking (boolean): Include overlapping chunks in the response. Default: false.
  • chunk_size_tokens (integer): Target chunk size in tokens. Default: 500.
  • overlap_size_tokens (integer): Token overlap between chunks. Default: 100.
  • output_content (boolean): Include cleaned content or article body. Default: true.
  • output_metadata (boolean): Include metadata and metrics. Default: true.
  • output_tables (boolean): Include markdown tables. Default: true.
  • output_code_blocks (boolean): Include code blocks. Default: true.
  • output_images (boolean): Include image markdown. Default: false.
  • output_links (boolean): Include hyperlinks. Default: false.

2. POST /v1/reader

Convert web content with extraction, output, tokenizer, and chunking options provided via a JSON request body. This is the recommended endpoint for production integrations.

Request Example

{
  "url": "https://example.com/article-url",
  "output_format": "markdown",
  "tokenizer": "openai",
  "mode": "generic",
  "force_dynamic": false,
  "disable_css": null,
  "enable_chunking": true,
  "chunk_size_tokens": 500,
  "overlap_size_tokens": 100,
  "output": {
    "content": true,
    "metadata": true,
    "tables": true,
    "codeBlocks": true,
    "images": false,
    "links": false
  }
}

Request Body Parameters

  • url (string, required): Target public webpage URL.
  • output_format (string): markdown, text, or json. Default: markdown.
  • tokenizer (string): openai, claude, gemini, or llama. Default: openai.
  • mode (string): article, documentation, product, forum, or generic. Default: generic.
  • force_dynamic (boolean): Force browser rendering instead of static retrieval. Default: false.
  • disable_css (boolean, nullable): Override site-rule CSS loading during dynamic rendering.
  • enable_chunking (boolean): Include overlapping chunks in the response. Default: false.
  • chunk_size_tokens (integer): Target chunk size in tokens. Default: 500.
  • overlap_size_tokens (integer): Token overlap between chunks. Default: 100.
  • output (object): Fine-grained output options.
  • output.content (boolean): Include cleaned content or article body. Default: true.
  • output.metadata (boolean): Include metadata and metrics. Default: true.
  • output.tables (boolean): Include markdown tables. Default: true.
  • output.codeBlocks (boolean): Include code blocks. Default: true.
  • output.images (boolean): Include image markdown. Default: false.
  • output.links (boolean): Include hyperlinks. Default: false.

3. POST /v1/reader/chunk

Split raw input text into overlapping token or character segments without fetching a webpage. Use this endpoint when you already have text and only need chunk preparation for embeddings or retrieval.

This endpoint currently keeps its original array response and legacy error shape. The standardized reader success/error envelope applies to GET /v1/reader and POST /v1/reader; chunk endpoint alignment is planned for a later milestone.

Request Example

{
  "text": "The long raw text content you want to split into overlapping chunks for embedding ingestion...",
  "tokenizer": "openai",
  "use_tokens": true,
  "chunk_size_tokens": 500,
  "overlap_size_tokens": 100
}

Request Body Parameters

  • text (string, required): Raw text to split.
  • tokenizer (string): openai, claude, gemini, or llama. Default: openai.
  • use_tokens (boolean): Use token-based chunking when true; use character-based chunking when false. Default: true.
  • chunk_size_tokens (integer): Target chunk size in tokens. Default: 500.
  • overlap_size_tokens (integer): Token overlap between chunks. Default: 100.
  • chunk_size (integer): Target chunk size in characters when use_tokens is false. Default: 1000.
  • overlap_size (integer): Character overlap when use_tokens is false. Default: 200.

Response Example

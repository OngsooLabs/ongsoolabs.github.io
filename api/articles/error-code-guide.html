Error Code Guide

AI Reader API failures use a stable error envelope with status = failed, zero usage, and an error object that clients can handle consistently.

execution.profile reports the internal execution strategy used for the response and is not a request option. For a retryable RENDER_REQUIRED error, recommendedProfile = "standard" is a hint to retry the same request with force_dynamic=true. Clients cannot select fast or standard directly.

Reader Error Codes

Code HTTP status Retryable Recommended client action
INVALID_URL 400 No Fix the missing or malformed URL before retrying.
INVALID_REQUEST 400 No Fix unsupported options, invalid payloads, or invalid parameters.
UNSAFE_URL 403 No Use a public URL that does not target local, private, or metadata network ranges.
RENDER_REQUIRED 422 Yes Retry the same request with force_dynamic=true.
BLOCKED_BY_SITE 422 No The target site blocked automated retrieval or returned unusable content.
FETCH_FAILED 502 Yes Retry later or verify that the target site is reachable.
INTERNAL_ERROR 500 Yes Retry later. Contact support if the error persists.

Retry Guidance

Retry when retryable is true, especially for transient fetch, rendering, or service errors. Use backoff and avoid aggressive repeated requests to the same target domain.

Do not retry unchanged requests for INVALID_URL, INVALID_REQUEST, or UNSAFE_URL. These require caller-side changes.

User Actionability

When userActionable is true, the caller can usually fix the request or choose a different target URL. When it is false, the failure is more likely to be temporary or service-side.

Chunk Endpoint

POST /v1/reader/chunk keeps its successful array response, but failure responses use the same standard error envelope shape.

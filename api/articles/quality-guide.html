Quality Guide

AI Reader API returns quality metadata to help clients judge whether extracted content is suitable for LLM, RAG, search, and summarization workflows.

Version

quality.version = qv0 means the quality block is currently signal-based. The API exposes measurable signals, but it does not yet claim a final universal quality score.

Score And Grade

score and grade are currently null by design.

Extraction quality depends on page type, language, layout, target-site behavior, and downstream use case. Until benchmark and regression gates are mature enough, the API avoids presenting an overconfident numeric score.

Confidence

confidence is a coarse indicator for how usable the extracted content appears. Treat it as a hint, not as a guarantee.

Signals

Signal Meaning
contentLength Length of the cleaned extracted content.
markdownLength Length of the Markdown/text output representation.
headingCount Number of detected headings in the output.
linkDensity Approximate share of visible Markdown link text in the extracted content. Image Markdown is excluded.
boilerplateRatio Reserved for future boilerplate estimation.
duplicateParagraphRatio Approximate share of repeated paragraphs.
codeBlockCount Number of detected fenced code blocks.
tableCount Number of detected table-like sections.
imageCount Number of image references included in the output.
languageDetected Detected or extracted language hint when available.
htmlToMarkdownRatio Ratio between extracted content length and original HTML length.
mainContentExtractionRatio Reserved for future main-content extraction measurement.

Recommended Use

For RAG pipelines, use the signals as filters or ranking hints. For example, very short content, high duplicate paragraph ratio, or unusually high link density may indicate that the page needs review or a different extraction mode.

For summarization, prefer content with enough contentLength and a moderate structure signal such as headings, tables, or code blocks when those elements matter to the target page.

Warnings

The warnings array is reserved for explicit extraction concerns. Clients should display or record warnings when present, but should not assume that an empty warnings array means perfect extraction.

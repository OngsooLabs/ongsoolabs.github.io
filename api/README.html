AI Reader API

AI Reader API is a public Ongsoo Labs service for converting web pages and public text-layer PDF documents into clean AI-ready content with usage, quality, and execution metadata.

Public access is available through RapidAPI. Direct calls to https://api.ongsoolabs.com are reserved for platform and partner integrations unless separately arranged.

Overview

Web page or PDF URL -> Safe retrieval -> Content extraction -> Markdown/text/JSON output -> Usage, quality, and execution metadata

Key Features

  • AI-ready content: Converts the main page content into Markdown, text, or structured JSON suitable for AI prompts and indexing.
  • Content and title extraction: Filters common navigation, layout, and advertising noise.
  • Contracted metadata: Returns usage, quality, and execution metadata for cost, confidence, and runtime visibility.
  • Standard errors: Returns stable error codes for invalid, unsafe, blocked, or failed reads.
  • Output options: Lets callers choose whether to include optional links, images, tables, and code blocks.
  • Reader modes: Supports content-oriented modes such as article, documentation, product, forum, and generic.

Authentication

Use the X-RapidAPI-Key and X-RapidAPI-Host values shown in your RapidAPI dashboard.

API Endpoints

Method Path Description
GET /v1/reader Text conversion and analysis using URL parameters
POST /v1/reader Advanced options through a JSON body
POST /v1/reader/document Public Beta: extract a public text-layer PDF URL as Markdown
POST /v1/reader/chunk Split text into chunks for downstream AI processing
GET /v1/diagnostics Deployment smoke diagnostics for direct platform operations

Quick Start: First Successful Read

  1. Create or sign in to your RapidAPI account and subscribe to an available AI Reader API plan.
  2. Copy your X-RapidAPI-Key from the RapidAPI dashboard.
  3. Run this request. It uses https://example.com/, a public page intended for integration examples.

macOS or Linux

curl --request POST \
  --url https://ai-reader-api.p.rapidapi.com/v1/reader \
  --header 'Content-Type: application/json' \
  --header 'X-RapidAPI-Host: ai-reader-api.p.rapidapi.com' \
  --header 'X-RapidAPI-Key: <your-rapidapi-key>' \
  --data '{
    "url": "https://example.com/",
    "output_format": "markdown",
    "mode": "generic",
    "enable_chunking": false
  }'

Windows PowerShell

$headers = @{
  "X-RapidAPI-Key" = "<your-rapidapi-key>"
  "X-RapidAPI-Host" = "ai-reader-api.p.rapidapi.com"
}

$body = @{
  url = "https://example.com/"
  output_format = "markdown"
  mode = "generic"
  enable_chunking = $false
} | ConvertTo-Json

$response = Invoke-RestMethod -Method Post `
  -Uri "https://ai-reader-api.p.rapidapi.com/v1/reader" `
  -Headers $headers `
  -ContentType "application/json" `
  -Body $body

$response.status
$response.content.value
$response.usage.credits
  1. A successful request returns HTTP 200, status: "success", non-empty content.value, and usage.credits: 1.

PDF Document Reader (Public Beta)

POST /v1/reader/document accepts a public HTTPS PDF URL and returns content.format = "markdown". The Public Beta supports text-layer PDFs only; it does not accept uploads, DOCX, OCR, encrypted PDFs, or document generation requests.

{
  "url": "https://example.com/report.pdf",
  "tokenizer": "openai",
  "enable_chunking": false
}

PDF retrieval revalidates each redirect against the URL-safety policy, limits downloads to 10 MB and parsing to 100 pages, and never uses browser rendering. execution.profile is document, execution.usedBrowser is false, and successful beta reads return usage.credits = 1. A document with some image-only pages returns available text with a PARTIAL_DOCUMENT_TEXT quality warning; a document with no extractable text fails with DOCUMENT_NO_TEXT_LAYER.

Execution Profiles and Render Retries

execution.profile is the internal execution strategy actually used for the read: fast represents a static path, and standard represents a browser-oriented path, including dynamic site rules, force_dynamic=true, or static-to-browser fallback. It is response metadata only; clients cannot select a profile.

For a retryable RENDER_REQUIRED error, error.recommendedProfile = "standard" means retry the same request with force_dynamic=true. It does not add a profile request option. Browser use, cache behavior, and execution profile do not change the successful-read credit: usage.credits = 1.

metadata.canonical_url, metadata.source_name, metadata.published_at, and language are best-effort page metadata. Missing or untrusted values are omitted. published_at uses structured JSON-LD, explicit article metadata, or a <time datetime> value; it is not inferred from page text. Language is omitted when it cannot be reliably detected. Author metadata is not part of the public v1 contract.

Credits and RapidAPI Quota

GET /v1/reader, POST /v1/reader, and successful POST /v1/reader/document calls use the v1 launch credit model:

  • Successful page reads return usage.credits = 1.
  • Failed page reads return usage.credits = 0.
  • Optional output controls, reader mode, browser fallback, cache validation, and in-response chunking do not change the launch credit value.

RapidAPI controls public request quota, enabled plans, overage pricing, bandwidth platform fees, billing, and subscription state. In the current RapidAPI configuration, the Requests object counts any endpoint call as one request.

Deployment Diagnostics

GET /v1/diagnostics is a low-cost smoke check for deployment verification. It is intended for direct platform and partner operations, not public RapidAPI traffic.

The endpoint does not scrape an external webpage. It checks API and Reader service registration, sanitized required-configuration state, cache read/write behavior, TextProcessor token-count connectivity, and Reader-to-Document-Parser worker reachability. It never returns internal service URLs, secrets, AWS identity details, Docker network details, or document content.

GET /v1/diagnostics
X-RapidAPI-Proxy-Secret: <proxy-secret>

Successful diagnostics return HTTP 200 with status = ok.

{
  "status": "ok",
  "checkedAtUtc": "2026-07-07T00:00:00Z",
  "durationMs": 24,
  "checks": [
    { "name": "api_pipeline", "status": "ok", "message": "API routing and controller execution are available.", "durationMs": 0 },
    { "name": "reader_service", "status": "ok", "message": "Reader service dependency is registered.", "durationMs": 0 },
    { "name": "configuration", "status": "ok", "message": "Required deployment configuration is present.", "durationMs": 0 },

    { "name": "text_processor", "status": "ok", "message": "TextProcessor token count check succeeded.", "durationMs": 22 }

If any check fails, the endpoint returns HTTP 503 with status = needs_attention; the failing check also uses status = needs_attention.

Local Development

Source development requires the .NET 10 SDK. Docker is used for containerized local and deployment environments.

For local reader development, run TextProcessor and Scraper together:

dotnet run --project C:\Project\OngsooLabs.Api\src\Services\TextProcessor\OngsooLabs.TextProcessor.WebApi\OngsooLabs.TextProcessor.WebApi.csproj --launch-profile http
dotnet run --project C:\Project\OngsooLabs.Api\src\Services\Scraper\OngsooLabs.Scraper.WebApi\OngsooLabs.Scraper.WebApi.csproj --launch-profile http

In Development, Scraper uses TEXT_PROCESSOR_URL = http://localhost:5176 from appsettings.Development.json.
